Самодостаточная спека. Продолжение принятого раунда 3 в этом же проекте
(`C:\Users\<USER>\Documents\Projects\MCP\Grok CLI`), тем же git-репозиторием, новыми коммитами.

**Задача владельца:** довести `grok_delegate` до состояния, когда ему можно доверять как MCP —
он покрывает нужные возможности CLI, умеет показывать статусы, корректно отрабатывает и
подключается в разные проекты. Ключевое требование: **проверяемость без перезапуска Claude**.

## Почему это отдельный раунд

Сейчас сервер умеет ровно одно — делегировать цель. Любая проверка «а он вообще жив?» требует
перезапуска Claude Desktop. Плюс раунд 3 честно оставил `../`-escape и OS-sandbox как не-гарантии,
а в CLI, как выяснилось, есть флаг `--sandbox`, который это закрывает по-настоящему.

## Реальная поверхность CLI (снято с `grok --help` на этом хосте — сверь сам, не доверяй списку)

Полезные флаги: `-p/--single`, `--prompt-file`, `--prompt-json`, `--output-format`,
`--permission-mode`, `--max-turns`, `--model`, `--cwd`, `--allow`, `--deny`,
`--disallowed-tools`, **`--tools`** (allowlist встроенных инструментов), **`--sandbox <PROFILE>`**
(«Sandbox profile for filesystem and network access», env `GROK_SANDBOX`), **`-w/--worktree`** +
**`--worktree-ref`** (родные worktree), `-r/--resume`, `-c/--continue`, `--fork-session`,
`-s/--session-id`, `--json-schema`, `--agents`, `--no-subagents`, `--rules`,
`--system-prompt-override`, `--reasoning-effort`, `--disable-web-search`, `--no-plan`, `--debug-file`.

Read-only подкоманды со **машиночитаемым** выводом: `doctor --json`, `inspect --json`,
`version --json`, `models`, `sessions list|search`.

## Задача A — статус-инструменты (без перезапуска Claude)

Добавить read-only MCP-тулы, чтобы состояние проверялось прямо из чата:

1. `grok_delegate_status` — сводка здоровья: найден ли бинарь `grok` и его версия (`version --json`),
   есть ли активная авторизация (**не читая** `auth.json` — только факт «сессия есть/нет», например по
   успеху безопасной read-only команды), доступен ли git, где сконфигурированы корни/lanes_parent,
   какие профили разрешений и sandbox активны. Возврат — структурированный JSON, а не текст.
2. `grok_delegate_doctor` — обёртка над `grok doctor --json` (**без** подкоманды `fix`).
3. `grok_delegate_models` — обёртка над `grok models`.
4. `grok_delegate_inspect` — обёртка над `grok inspect --json` для указанного (разрешённого) проекта.

Все четыре — строго read-only, bounded timeout, без мутаций.

## Задача B — мультипроектность (это сейчас сломано)

Фикс R5 сделал `resolve_trusted_repo_root` fail-closed на любой клиентский `repo_root`, поэтому
сервер не может обслуживать несколько проектов. Нужна модель, которая **и** безопасна, **и**
многопроектна:

- **Allowlist корней** через env/конфиг (например `GROK_DELEGATE_ALLOWED_ROOTS` — список путей через
  `;`, либо JSON-конфиг рядом с сервером). Клиентский `repo_root` принимается **только** если он
  строго входит в allowlist (после `resolve()`, с защитой от `..` и симлинков).
- Для каждого корня — свой `lanes_parent` (по умолчанию `<root>/../pcp-lanes` или отдельный
  сконфигурированный путь), с сохранением проверки «worktree не внутри рабочего дерева репо».
- Пустой/несконфигурированный allowlist → fail-closed с внятной ошибкой и подсказкой, что настроить.
- `grok_delegate_status` показывает список разрешённых корней — чтобы было видно без гадания.

Добавить тесты: корень из allowlist принят; корень вне allowlist → отказ; `..`-обход → отказ;
пустой allowlist → fail-closed.

## Задача E — самопроверка без Claude (главное требование)

Сделать так, чтобы уверенность в сервере не требовала перезапусков Claude Desktop:

1. `python -m grok_delegate --self-test` — прогон, который: находит бинарь, снимает версию,
   проверяет авторизацию, поднимает stdio-цикл в процессе, выполняет `initialize` → `tools/list` →
   вызов каждого read-only статус-тула, печатает таблицу PASS/FAIL и возвращает ненулевой код при
   провале. **Без** мутаций и без реального делегирования.
2. `python -m grok_delegate --smoke-delegate` (или отдельный скрипт) — **реальный** bounded прогон
   plan-only делегирования во временной директории: доказывает, что headless действительно
   отрабатывает и выходит. Не мок.
3. Оба режима задокументировать в README как «как проверить, что MCP жив».

## Жёсткие границы (обязательны)

- **Никаких деструктивных/мутирующих поверхностей CLI наружу.** Запрещено выставлять MCP-тулами:
  `sessions delete`, `doctor fix`, `logout`, `update`, `setup`, `plugin *`, `mcp *` (управление
  конфигурацией), любые операции, меняющие состояние установки Grok или его конфиги.
- Сохраняются **B1–B9** из раунда 3: worktree-изоляция, никогда `--always-approve`, никогда
  `bypassPermissions`, fail-closed, без auto-merge/push, bounded turns+timeout, audit без секретов,
  `auth.json` не читаем и не логируется.
- `grok_bin` по-прежнему **не** принимается от клиента.
- Статус-тулы не должны раскрывать секреты: только факт наличия сессии, без токенов и путей к ним.
